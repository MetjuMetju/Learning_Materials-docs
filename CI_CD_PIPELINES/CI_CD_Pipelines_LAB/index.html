    CI CD Pipelines LAB

    CI = Continuous Integration

    - Get the source code
- Build the image
- Run application tests
- Scan the image
- Reject bad builds

    CD = Continuous Delivery/Deployment

    - Take the approved image
- Push/store it in the registry
- Deploy it to Kubernetes
- Verify the deployment
- Roll back if deployment fails

    CI Stages (source):

    - build
- test
- scan

    CD Stages (GHCR approved image):

    - push
- deploy (Kubernetes deployment)
- verify (rollout verification, application test)

    PHASE 1 - APPLICATION

    ### 1. CREATE GITHUB REPOSITORY
# Create a new repository, for example: nginx-ci-cd
cd nginx-ci-cd

### 2. CREATE WEB APPLICATION
# We will use a minimal static HTML application served by nginx.
vi index.html

# Content:
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>CI/CD Demo</title>
</head>
<body>
    <h1>CI/CD Demo Application</h1>
    <p>Version: 1.0.0</p>
</body>
</html>

### 3. ADD HTTPS SUPPORT
# nginx will terminate HTTPS (endpoint of the HTTPS/TLS connection).
# We need:
    HTTPS
    TLS certificate
    TLS private key
    nginx HTTPS configuration

# We do NOT put a real private key into GitHub.
# For local development, the certificate will be generated by the Docker Compose TLS bootstrap service.
# For production, the certificate should come from a proper certificate authority or secret-management system.

### 4. ADD APPLICATION VERSIONING
# Create file named:
vi VERSION
# Content:
1.0.0

# The application version is now explicitly stored in the repository.

# We can later use this same version when creating the container image:
myapp:1.0.0

# and eventually:
ghcr.io/<owner>/nginx-ci-cd:1.0.0

    PHASE 2 - CONTAINER

    ### 5. CREATE MULTI-STAGE DOCKERFILE

# We need two stages:
development
production

# Create:
vi Dockerfile

# CONTENT:
FROM nginx:alpine AS development
COPY index.html /usr/share/nginx/html/index.html

FROM nginx:alpine AS production
COPY index.html /usr/share/nginx/html/index.html


### 6. ADD DEVELOPMENT DOCKER TARGET

# Build it:
docker build --target development -t nginx-ci-cd:dev .

### 7. ADD PRODUCTION DOCKER TARGET

# Build it:

docker build --target production -t nginx-ci-cd:1.0.0 .

    PHASE 3 - DOCKER COMPOSE

    ### 8. CREATE DOCKER COMPOSE FOR LOCAL DEVELOPMENT

# Create:
vi compose.dev.yml

# CONTENT:
services:
  tls-bootstrap:
    image: alpine/openssl
    volumes:
      - ./certs:/certs
    command:
      - req
      - -x509
      - -nodes
      - -days
      - "365"
      - -newkey
      - rsa:2048
      - -keyout
      - /certs/server.key
      - -out
      - /certs/server.crt
      - -subj
      - /CN=localhost

  web:
    build:
      context: .
      target: development
    depends_on:
      tls-bootstrap:
        condition: service_completed_successfully
    ports:
      - "8443:443"
    volumes:
      - ./index.html:/usr/share/nginx/html/index.html:ro
      - ./nginx/dev.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certs:/etc/nginx/certs:ro


### 9. CREATE DOCKER COMPOSE FOR PRODUCTION

### 10. GENERATE TLS CERTIFICATES

# Create:
mkdir -p certs

# The bootstrap service generates:
certs/server.crt
certs/server.key

# Run for local development:
docker compose -f compose.dev.yml up --build

# The certificate is self-signed.
# That is acceptable for LOCAL DEVELOPMENT.

# Test:
curl -k https://localhost:8443

# The "-k" is needed because the certificate is self-signed.


### 11. CONFIGURE APPLICATION FOR HTTPS

# Create:
mkdir -p nginx
vi nginx/dev.conf

# CONTENT:
server {
    listen 443 ssl;
    server_name localhost;

    ssl_certificate /etc/nginx/certs/server.crt;
    ssl_certificate_key /etc/nginx/certs/server.key;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

# Create:
vi nginx/prod.conf

# CONTENT:
server {
    listen 443 ssl;
    server_name localhost;

    ssl_certificate /etc/nginx/certs/server.crt;
    ssl_certificate_key /etc/nginx/certs/server.key;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

# nginx listens on:
443

# Application is accessed with:
https://localhost:8443


### 12. VERIFY PRODUCTION

# Stop development:
docker compose -f compose.dev.yml down

# Start production:
docker compose -f compose.prod.yml up --build

# Test:
curl -k https://localhost:8443
